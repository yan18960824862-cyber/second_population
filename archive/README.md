# 娜娜负责的档案模块

本次修改在 `nana-archive` 分支，包含通用物体档案的加载、进场、数据说明和骑手案例。原有空调专用模块 `ac-archive/` 保留。

## 查看方式

在项目根目录运行 `python nocache_server.py`，浏览器打开 `http://127.0.0.1:8020/index.html`。进入系统后点击“外卖骑手”识别框或档案卡片。

- 加载：小窗口展开、线框逐步补齐、连续旋转两圈、完成后淡出。时间线来自空调版，正常模式 6.6 秒。
- 档案：依次显示边框、主图、身份信息、局部图、碳记录和资源连接。
- 骑手加载造型由网页代码生成，WebGL2 绘制；不支持 WebGL2 时使用 Canvas 后备绘制。没有模型软件或外部服务依赖。
- 档案图片是生成的示意素材，并非实物扫描。能源模块底图稳定，仅保留缓慢移动的电流示意光点。
- 碳排放资料不足时显示 `DATA PENDING`；单个无表情图标的 `PENDING` 表示待评估，不代表中等排放。
- 可使用返回、上一目标、下一目标和回放；退出或回放会停止先前的动画。

## 合并涉及的文件

- `index.html`：增加本目录的样式、脚本和档案字段。
- `tracker.js`：连接加载/档案状态、数据说明、局部动画和回放。
- `model-loader/model-engine.js`：模型扩展接口、共享时间线及开场缩放下的尺寸修复。
- `panels.js`：骑手卡片采用独立、清晰的线条缩略图。
- `archive/`：模块代码及配套素材。

`sequence.js` 负责时间线；`rider-approved.js` 负责当前骑手造型，`rider-gpu.js` 负责显卡绘制；`rider-geometry.js` 同时保留卡片缩略图和 Canvas 后备接口。`motion.js` 负责档案图故障效果与能源示意动画。

`turntable.js` 和部分历史素材保留为设计过程备份，目前没有接入页面；当前加载使用连续三维旋转，不使用八张角度图切换。

## 数据边界

原 `tracks.json` 明确将环境数据标注为模拟估算。本模块不将无来源的制造能耗、用水或年碳排放当作实测结果。实际核算需要车型、能源记录、统计期及有来源的排放因子；制造和使用阶段分开记录。方法及缺失资料可在 `SOURCE NOTES` 查看。
